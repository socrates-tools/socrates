# 5.2: One live run per skill under a real Codex, recorded

## What to build

Each skill is run once under a real `codex` and recorded, so what the spec read from Codex's source and documentation is seen once: the loopback bind refused under the sandbox and served after the escalation, a subagent inheriting the writable root, and the role's model and effort applied to a spawn.

## Acceptance criteria

- [ ] A design over agora was run under a real `codex` and recorded, including whether `socrates agora serve` was refused before escalation and whether the person was asked.
- [ ] A review was run under a real `codex` and recorded, including which reviewer CLI it spawned.
- [ ] An implementation of one ticket was run under a real `codex` and recorded, including the overseer's check of the writable root with and without it granted.
- [ ] Anything the runs contradict in the spec or the renderings is raised as a ticket or an issue rather than left in the record.
