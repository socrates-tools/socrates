# 3.2: The reviewer follows the host where nobody set one

## What to build

A person who starts a review from Codex with no `reviewer_cli` set gets `codex` as the reviewer, and one started from Claude Code gets `claude` as today.
A `reviewer_cli` a person set wins whatever the host, and every round of a run is reviewed by the CLI its first round was.

## Acceptance criteria

- [ ] `socrates review begin --host codex` with `reviewer_cli` unset spawns the `codex` reviewer, and `--host claude` or no `--host` spawns `claude`.
- [ ] `begin --host codex` with `reviewer_cli: claude` spawns `claude`.
- [ ] A `continue` on a run begun with `--host codex` spawns `codex` again, whatever `--host` it is given.
- [ ] A `--host` naming neither host is refused before a snapshot is taken.
- [ ] Which vendor each host maps to is stated inside the reviewer seam, and nothing above it names a vendor.
- [ ] `socrates review config` reports `reviewer_cli` as the file states it and says an unset one follows the host a review begins from.
- [ ] The Codex rendering of both review skills passes `--host codex` to `begin`, and the Claude Code rendering passes `--host claude`.
- [ ] ADR 60 names ADR 69 as amending it, and review's instruction file states the invariant.
