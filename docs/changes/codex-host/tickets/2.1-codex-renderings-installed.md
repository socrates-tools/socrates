# 2.1: Every skill installs for Codex too

## What to build

Codex becomes the second host.
`socrates skill` and each namespace's `skill` write Codex's rendering of every skill under `~/.agents/skills` beside Claude Code's, whatever is on `PATH`.
A Codex skill is person-only by `agents/openai.yaml` beside it, its front matter holds only its name and description, its Installing elsewhere section names Codex's directories and `--host codex`, and a skill that names the next one a person starts names it as `$<name>`.
`--to` and `--agents-to` need `--host`.

## Acceptance criteria

- [ ] `socrates skill` under a fresh home with no `codex` on `PATH` writes every skill under both `~/.claude/skills` and `~/.agents/skills`.
- [ ] Every Codex skill has `agents/openai.yaml` beside it holding `allow_implicit_invocation: false` under `policy`.
- [ ] A Codex `SKILL.md` carries `name` and `description` in its front matter and no other key.
- [ ] A Claude Code skill is unchanged.
- [ ] `--to` or `--agents-to` without `--host` is refused, naming `--host`, before anything is written, and `--host codex --to <dir>` writes Codex's rendering there and nothing else.
- [ ] `--host` alone writes only that host's rendering to its default directory.
- [ ] The person-only check over every committed skill and over everything a `skill` operation installs reads each host's own switch, and fails where a Codex skill loses its `openai.yaml` as it fails where a Claude Code skill loses its field.
- [ ] `make skill` commits Codex's renderings under `.agents/skills`, and the suite fails where one disagrees with what the package renders.
- [ ] ADR 49 names ADR 67 as amending it, and the suite's instruction file states the person-only invariant per host.
