# 3.1: On Codex, the page is served with the person's approval

## What to build

A person running `$socrates-design`, `$socrates-tickets`, `$socrates-review` or `$socrates-review-handover` in Codex gets the page without changing their Codex sandbox.
The Codex renderings tell the session to run `socrates agora serve`, `socrates agora poll` and `socrates agora end` outside the sandbox by asking the person, and to run in subagents, started and collected Codex's way, what the Claude Code renderings run in the background.

## Acceptance criteria

- [ ] Each of the four Codex renderings tells the session to run `socrates agora serve`, `poll` and `end` with `sandbox_permissions` set to `require_escalated` and a one-line justification naming the page.
- [ ] Where a Claude Code rendering sends work to a subagent or to the background, the Codex rendering says to start it with `spawn_agent` and collect it with `wait_agent`, waiting briefly enough to answer the person between waits.
- [ ] No Claude Code rendering names `require_escalated`, `spawn_agent` or `wait_agent`, and no Codex rendering describes Claude Code's background work.
- [ ] Every Codex rendering still tells the session to invoke no skill.
- [ ] Each rendering stays within its ceiling.
