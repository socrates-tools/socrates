# 3.3: The implementer is installed as a Codex role

## What to build

`socrates implement skill` writes the implementer as a Codex role beside Claude Code's agent definition, so a Codex overseer can spawn it.
The role carries the implementer's name, description and standing instructions and its effort, `high` by default, and nothing Codex would refuse.
Where the role was written is recorded beside where Claude Code's definition was.

## Acceptance criteria

- [ ] `socrates implement skill` writes `socrates-implementer.toml` under `$CODEX_HOME/agents`, or `~/.codex/agents` where `CODEX_HOME` is unset, creating the directory where it does not exist.
- [ ] The role, read as TOML, holds only `name`, `description`, `developer_instructions`, `model_reasoning_effort` and, where one is set, `model`, and the suite fails on any other key.
- [ ] Its standing instructions are the ones Claude Code's definition carries, and it names no `socrates` command.
- [ ] `--host codex --agents-to <dir>` writes the role there.
- [ ] The installation record holds one directory per host, and a record in today's shape is read as Claude Code's.
- [ ] `make skill` commits the role under `.codex/agents`, and the suite fails where it disagrees with what the package renders.
