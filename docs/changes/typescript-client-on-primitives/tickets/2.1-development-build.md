# 2.1: A development build serves the bundle from disk and rebuilds it on save

## What to build

A contributor runs one make target that builds socrates with a development build tag and starts the bundle's build in watch mode.
A binary built with the tag serves the page's assets from the bundle directory on disk instead of its embedded copy, so a rebuilt bundle is what the next reload sees.
The watch mode type-checks on every save and prints what it finds without stopping.
A binary built without the tag has no way to serve assets from anywhere but its embed.

## Acceptance criteria

- [ ] `make dev` starts a watch that rebuilds the bundle within a few seconds of saving a client source, and `make help` names it.
- [ ] A page served by the development build shows an edited stylesheet or script after a reload, with no rebuild of the binary.
- [ ] A type error saved during the watch is printed and the watch keeps running, and fixing it rebuilds the bundle.
- [ ] A binary built without the tag serves the embedded bundle even when the bundle on disk has changed.
- [ ] `CONTRIBUTING.md` names `make dev` and still says Node and pnpm are needed only by somebody who touches the client.
