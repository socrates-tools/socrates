# 3.1: The dialog is the first primitive, and the contract holds it to its markup

## What to build

This is the tracer bullet for every primitive after it.
The library declares its first primitive, the dialog, in its contract: the element's name and the parts it holds.
The build writes the contract out for Go to read, as it already writes the languages the page highlights.
The dialog's markup is a Go partial written once, and a Go test fails where any partial writes an element or a part the contract does not declare, or where a declared one is written by no partial.
The dialog is a custom element without a shadow root, whose behaviour is attached when it enters the page and released when it leaves, and which offers opening and closing as methods of its own.
The confirmation is rebuilt on it, keeping its own class, so the browser suite finds it as before.

## Acceptance criteria

- [ ] The confirmation on the page is a `ui-dialog` element carrying the confirmation's class, and every browser test about the confirmation passes unchanged.
- [ ] Removing a part from the dialog's partial, adding an undeclared part to it, or declaring a part no partial writes each fails the suite, naming the element and the part.
- [ ] Changing the dialog's markup needs no Node: the contract check reads the committed contract.
- [ ] After a revision replaces the surface, the dialog that was on the page before answers nothing: no listener of it reacts to a key or a press.
- [ ] Escape, a press on the backdrop and going back still close the confirmation and return the cursor to the button that raised it.
