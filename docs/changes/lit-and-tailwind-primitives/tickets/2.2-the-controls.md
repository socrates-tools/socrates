# 2.2: The button, the field, the copy control and the expand control as Lit elements

## What to build

The button, the text field, the copy control and the expand control are Lit elements rendering into shadow roots, styled with utilities, and each exposes what its callers need: a field's `value` and `focus()`, a button's `disabled` and `click()`, the copy control's `copyrequested` event and the expand control's `expanded` and `collapsed` events.
The surface's script sends, confirms, amends, copies and expands through those properties and events alone, and the browser suite clicks, types at and reads them by their element and class, so `.send` is the `<ui-button>` and `.words-field` the `<ui-field>`.
A person answering a page types, sends, copies code and expands a drawing as they do today.

## Acceptance criteria

- [ ] Each of the four has a shadow root on the page and in the catalog, and every state the catalog draws of each looks as it did before.
- [ ] Clicking or focusing a button or a field's element reaches the control inside it, and Enter in a field still sends rather than finishes.
- [ ] What a person typed in a decision's words field and in the message is what is sent, read through the field's own `value`.
- [ ] Every code block's copy control still puts the code on the clipboard exactly as the document stated it, says what it does on hover, on focus and to a screen reader, and confirms the copy where it was pressed.
- [ ] Expanding and collapsing a drawing behaves as it did.
- [ ] Each one's partial writes only the element, its declared attributes and its slotted content, held by the Go contract test.
