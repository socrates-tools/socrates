# 3.2: socrates implement configure changes one setting from a menu

## What to build

`socrates implement configure` draws a menu of the same settings `socrates implement config` reports, read from the same place, built on the shared menu machinery.
A person changes one setting, and only the key they confirmed is written, as soon as they confirm it.
A confirmed model or effort also rewrites the installed agent definition wherever it was recorded as installed, so the next implementer spawned runs on it.
Where no definition has been installed, the setting is written and the menu says the definition is written by `socrates implement skill`.
Run inside a repository, the menu also offers that repository's default branch, where *use the default* removes the entry.
It refuses where nothing is a terminal, naming `socrates implement config`.

## Acceptance criteria

- [ ] Driven in a real pseudo-terminal, a confirmed `concurrency` lands in the file and `config` reports it as set.
- [ ] A confirmed model or effort lands in the file and in the installed definition at once.
- [ ] With no definition installed, the setting lands and the menu says how the definition is written.
- [ ] *Use the default* removes the line, and an emptied block goes with its last setting.
- [ ] Inside a repository the menu offers its default branch, and removing it leaves the other repositories' entries alone.
- [ ] A value the loader would refuse is refused before the file is touched.
- [ ] Run where nothing is a terminal, it refuses naming `socrates implement config`.
