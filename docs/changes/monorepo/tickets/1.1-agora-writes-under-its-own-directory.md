# 1.1: agora writes under its own directory

## What to build

What agora writes about itself and its pages moves out of review's directory and into agora's own, beside the configuration file agora already reads there.
agora reads `~/.socrates/agora/config.yaml` today, and still writes `surface.json` and `sessions/` under `~/.socrates/review/surface/`.

- agora writes under `~/.socrates/agora/`, and nothing of agora's resolves a path under review's directory.
- `SOCRATES_HOME` still moves the whole root, so one variable still moves everything every tool writes.
- `AGORA_HOME` stays retired, and the refusal that says so stands, with its wording corrected to name the brand's root rather than one home both binaries share.
- `README.md`, the surface invariants in `AGENTS.md`, and the line saying both tools write under `~/.socrates/review`, follow.
- Nothing migrates an existing `~/.socrates/review/surface/`: it holds a server record and page sessions, and a stopped surface loses nothing a person needs.

## Acceptance criteria

- [ ] A stated root holds `review/` and `agora/`: review's holds the runs and its configuration, and agora's holds its configuration and what the surface writes.
- [ ] Nothing of agora's lands in review's directory.
- [ ] Nothing lands in `~/.agora`, `~/.config/agora` or `~/.local/state/agora`.
- [ ] `AGORA_HOME` is still refused, naming the root.
