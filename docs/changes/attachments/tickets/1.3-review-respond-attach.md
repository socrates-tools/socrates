# 1.3: socrates review respond records attachments

## What to build

`socrates review respond --attach <path>`, repeatable up to ten, copies each file into the run store beside the response, and the next round's prompt names each attached file's path and type beside what the author said, so the reviewer reads it with its own read tool.
`--attach` is accepted with every resolution but forwarded, and refused on a forward naming why: a forward posts the finding to a pull request, and a forge has no plain route for a file.
`README.md`'s statement of where what socrates review reads goes names attachments in both directions: agora sends nothing, and a file recorded with `--attach` is read by the reviewer CLI, which sends it to its vendor.

## Acceptance criteria

- [ ] `respond --attach` with a decided, rejected, dropped or fixed resolution copies each file into the run store, and the copy survives the original being deleted.
- [ ] `respond --forwarded --attach` is refused naming why, and records nothing.
- [ ] An eleventh `--attach` is refused naming the ceiling, and a path that does not exist is refused naming it.
- [ ] The next round's prompt names each attached file's path and type for that finding.
- [ ] `README.md` says a file recorded with `--attach` is sent to the reviewer CLI's vendor, beside saying socrates review sends nothing.
