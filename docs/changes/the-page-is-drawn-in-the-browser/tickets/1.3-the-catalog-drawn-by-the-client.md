# 1.3: The catalog is drawn by the client

## What to build

Under the development build, the catalog is drawn by the client from states stated beside the library, with the same primitives, the same bundle and the same three widths as today.
Every primitive the library declares is drawn in every state it has, and one it declares that the catalog does not draw fails the suite, naming it.
A released binary still answers the catalog with not found.

## Acceptance criteria

- [ ] Changing a primitive's state in the catalog states beside the library changes what the catalog draws, with no Go change.
- [ ] A primitive the library declares that the catalog does not draw fails the suite naming it, read from the library rather than from the contract.
- [ ] Every catalog test in the browser suite passes against the client-drawn catalog with its selectors unchanged.
- [ ] A released binary answers the catalog with not found.
