# 1.1: The page's document is served as JSON with types generated from Go

## What to build

The surface answers, on a route of the session guarded by its token, the document it holds as the caller wrote it, beside what only the server knows: the revision, whether the exchange is over, each decision's illustration address, what is answered and the most files a tray holds.
The client's types for both are generated from the Go structs when the assets are built, and committed.
The suite fails while the committed types differ from what Go would generate, and the check runs without Node.
Nothing draws from this yet: the page a person opens is unchanged.

## Acceptance criteria

- [ ] A request for a session's document carrying that session's token returns the validated document and the server part; one carrying no token or another session's token is refused as every guarded route refuses it.
- [ ] After a revision, the document returned is the new one and the revision it states has moved on.
- [ ] Every illustration address returned opens that decision's copy of its illustration.
- [ ] Editing the committed client types by hand makes the suite fail naming them, on a machine with no Node.
- [ ] Adding a field to the document in Go without rebuilding the assets makes the suite fail.
